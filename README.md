# go-costmap-replanner-go

移动机器人局部代价地图 + 动态重规划的最小可运行实现。
链路：多路传感器读数并发接入 → 校验与融合为局部代价地图 → 基于一致性快照的
A\* 路径规划 → 动态障碍触发重规划（带抖动抑制）。

## 坐标与时间约定

- **坐标系**：平面直角坐标系，单位米。地图原点 `OriginX/OriginY` 是栅格 `(0,0)`
  的角点（不是中心），栅格 `(gx,gy)` 覆盖
  `[OriginX+gx*res, OriginX+(gx+1)*res) × [OriginY+gy*res, ...)`。
- **栅格量化**：`WorldToGrid` 用 `floor((x-OriginX)/res)`。落在栅格边界上的坐标
  对浮点误差敏感，模拟/接入数据时建议使用栅格中心坐标（如 `x.05`，res=0.1 时）。
- **时间戳**：每条读数自带 `Stamp`（观测时刻），`Ingest` 需要调用方传入当前时间
  `now`。系统不自建时钟，便于测试复现。容忍 200ms 的时钟超前（不同传感器时钟偏差）。
- **路径点**：规划输出的 `Path` 是地图坐标系下的栅格中心点序列。

## 代价地图更新规则

- 更新以**批次**为单位：`Ingest(now, batch)` 在同一个写锁内完成全部校验与融合，
  读者（`Snapshot`）只能看到批次提交前或提交后的状态，**不存在半提交**。
  批次中只要有一条读数被接受，版本号 `Version` 就且只前进一次。
- 每条读数独立校验，被拒绝的读数**不进地图**，并返回可区分的原因：

  | 拒绝原因 | 含义 |
  |---|---|
  | `corrupt` | 坐标/距离/置信度含 NaN、Inf，距离为负，或置信度超出 [0,1] |
  | `future_timestamp` | 时间戳超前 `now` 超过 200ms 容忍 |
  | `stale` | 读数年龄超过 `MaxAge` |
  | `out_of_order` | 时间戳早于**同传感器**已应用的最新读数（按 `SensorID` 分别跟踪） |
  | `out_of_bounds` | 命中点越出地图边界 |

  校验顺序固定（corrupt → future → stale → out_of_order → out_of_bounds），
  同样输入必然得到同样结论。
- **融合语义**：命中栅格代价 = `ObstacleCost × Intensity`；膨胀半径
  `InflateRadius` 内按 `(1 - dist/InflateRadius)` 线性衰减。融合取 **max**，
  重复观测不会无限累积，同一批数据重放结果一致。
- 代价 ≥ `ObstacleCost`（默认 254）的栅格为**致命障碍**，规划禁止通过；
  膨胀区代价只影响路径代价，不禁止通行。

## 规划与重规划

- `Plan(snapshot, cfg, req)` 在**调用时的一致性快照**上规划，结果带 `Version`
  字段标明所基于的地图版本，便于核对"这次规划看的是哪份地图"。
- 搜索为 8 连通 A\*：邻域扩展顺序固定、堆比较键 `(f, h, seq)` 全序，
  **同样的 (快照, 请求, 规划器历史) 必然复现同样的结论**（路径、代价、
  扩展节点数 `Explored` 都一致）。禁止穿过两个对角障碍的夹缝。
- **差速底盘约束**：`MinTurnRadius` 换算为最大曲率。A\* 路径先视线拉直，
  再对曲率超限的拐点确定性地回插原始路径点修复；当前航向 `Heading` 以虚拟
  前驱点参与第一个转弯的曲率检查。修复后仍超限则报 `curvature_infeasible`。
- **重规划触发条件**（由调用方驱动，典型做法）：
  1. 新传感器批次使地图 `Version` 前进；
  2. 动态障碍使旧路径在当前快照上失效（`pathStillValid` 内部判定）；
  3. 目标或底盘位姿变化。
- **抖动抑制（滞后切换）**：新路径代价须优于旧路径代价的
  `(1 - SwitchMargin)` 才切换；否则保留旧路径并在 `Detail` 中说明。
  障碍短暂抖动不会导致路径来回切换（见 `TestHysteresisStability`）。

## 规划失败原因

| 原因 | 含义 |
|---|---|
| `start_invalid` | 起点越界或落在致命障碍上 |
| `goal_invalid` | 目标越界或落在致命障碍上 |
| `goal_unreachable` | 目标栅格被致命障碍（或边界）完全包围 |
| `no_path` | 搜索耗尽，起点与目标不在同一连通区域 |
| `curvature_infeasible` | 存在几何通路但不满足最小转弯半径约束 |

成功时 `Cost` 为含障碍代价惩罚的总代价，`Explored` 为扩展节点数，
两者都可用于解释与复现核对。

## 本地验证

```bash
go build ./...          # 编译
go test ./... -v        # 单元测试（日志打印关键输入与判定依据）
go test ./... -race     # 并发竞态检测
go run ./cmd/sim        # 全链路演示：异常读数拒绝 → 规划 → 动态障碍重规划 → 目标被围
```

测试覆盖：乱序/过期/越界/损坏/未来时间戳读数、批次原子性、并发读写一致性
（无半提交、版本号单调）、静态/动态障碍绕行、目标被围、端点非法、
曲率不可行、噪声抖动下的路径稳定性、并发规划与更新、结论可复现。
